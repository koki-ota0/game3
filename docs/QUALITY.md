# ゲームの「クオリティ」を分解する（N.K. Works 実物のコードを読んで）

調査日: 2026-11-24
対象: `nkworks-games/nkworks-games.github.io` の実ゲームHTML（`hamidashi-tower` 84KB, `butter-hashimade` 84KB）
方法: 公開リポジトリの HTML を落として、CSS・シェーダ・音・ゲームループ・採点を直接読んだ。

> 目的: 「なぜ彼のゲームは安っぽく見えないのか」を、真似できる粒度まで分解する。
> ここに書いたのは**手法**であって、作品そのものではない。同じ題材・同じ見た目は作らない。

---

## 結論: クオリティは「4つの層」で決まっている

| 層 | 彼がやっていること | 素人が抜かすところ |
|---|---|---|
| 1. 企画 | 1文で説明できるルール + 「外に出る／破れる／落ちる」など**物理的な気持ちよさ** | ルールが2文以上、説明が必要 |
| 2. 見た目 | **世界観をひとつに絞る**（設計図 / 喫茶店）。色数は5色以内、背景まで作り込む | 背景が単色、色数が多い、フォントがバラバラ |
| 3. 手触り | カメラのlerp、画面の揺れ、振動、音の減衰、待ち時間ゼロ | 瞬間移動、無音、0.3秒の空白 |
| 4. 失敗の設計 | 失敗の**理由が画面に出る**、もう一度が1タップ、自己ベストの線が見える | 「ゲームオーバー」だけ |

---

## 1. 企画の型

`はみ出しタワー` の説明文:
> 手でつまんだ積み木を、前のブロックより少しでも外へ。出ていなかったら即終了。

`バターは端まで`:
> トーストを焼いて、20秒でバターやジャムをきれいに塗る。塗り残し・ムラ・はみ出しで採点。

**共通する構造**
- **動詞がひとつ**（積む / 塗る）
- **成功条件が「前より◯◯」という相対**（絶対値ではない）→ 難易度が自動で上がる
- **失敗が即座で、理由が明快**（外に出ていなかった / 破った）
- **数字が画面に出る**（はみ出し 0.00 / 何個積めた）
- 題材が**日常の「あるある」**（バターを端まで塗る、積み木をずらす）

---

## 2. 見た目: 世界観をひとつに絞る

### はみ出しタワー = 「設計図（ブループリント）」

```css
--bg:#0e3a68; --bg2:#0b2f57;
--line:#eaf6ff; --dim:#9fc3e6;
--cyan:#6fe3ff; --yellow:#ffd166; --red:#ff6b57; --green:#57f2b0;
--mono:'M PLUS 1 Code', monospace;   /* 等幅＝図面っぽさ */
```
- 背景 `#0e3a68` の**紺一色**。地面も壁も無い。方眼だけ。
- 面はフラットな塗り＋**白い輪郭線**。影は使わず、法線で明度を変えるだけ
  （`shade = 0.84 + 0.2*vN.y + 0.06*max(vN.z,0) - 0.08*abs(vN.x)`）
- 輪郭線は**シェーダで UV の端からの距離**から描く（太さは画面ドットで一定）
  → 線が常に1.2pxで、遠近でも太らない ＝ 図面らしさ
- 方眼はフラグメントシェーダで `fwidth` を使い、**遠くと消える**（モアレ防止）
- 破線（`1px dashed`）を UI の区切りに使う ＝ 図面の注記
- 角に**8pxのL字マーク**（`.bp:before/:after`）＝ 図面の用紙枠
- 影の代わりに、**「1/2」「1/4」の寸法ラベル**を箱に付ける

**学び**: 3Dで影を落とすより、「線＋フラット塗り＋方眼」のほうが安っぽくならない。
**影は情報を増やすが、線は情報を減らす。**

### バターは端まで = 「喫茶店」

```css
background:#f1e3cb;  color:#4a2f17;   /* クリーム色 × 焦げ茶 */
```
- `MeshStandardMaterial` + `roughness` でバターの**照り**を出す
- 木目・タイル・お皿を `CanvasTexture` で**その場で描く**（画像ファイル無し）
- `PlateGeometry` + `TorusGeometry`（縁の青い線）で食器らしさ
- 角丸フォント（M PLUS Rounded 1c）+ 丸ゴシック

**学び**: 同じ作者でも**作品ごとに世界観を変えている**。共通なのは「色数を絞る」ことだけ。

## 3. 手触り（ここが一番差がつく）

コードから拾えた具体策:

| 手法 | 実装 |
|---|---|
| カメラ追従 | `cam.L.lerp(cam.gL, 1 - exp(-dt*4.5))` — フレームレート非依存の指数補間 |
| 画面の揺れ | `cam.shake *= exp(-dt*16)`、`(Math.random()-0.5)*shake` を位置に加算 |
| 振動 | `navigator.vibrate(pattern)` を `try/catch` で包む（iOSでは無い） |
| 音 | `AudioContext` を**1つだけ**作り、`createGain` で包んで master 音量。`exponentialRampToValueAtTime` で 0.0001 まで落とす（プチノイズ防止） |
| ノイズ音 | 1秒のホワイトノイズバッファを**1回だけ作り回す** + `BiquadFilter` で質感を変える（打撃・紙・水） |
| 失敗表示 | 画面下に**理由のカード**を0.35秒で出す（`cardIn` アニメ） |
| 予告 | 次のブロックを**半透明の赤**で表示（`fillA: 0.03, lineA: 0.4`）＝ 「ここに置くよ」 |
| 記録 | 自己ベストを**3Dの線**として盤面に引く |
| 待ち時間 | タイトル→プレイは**アニメーションで繋ぐ**（暗転しない） |

---

## 4. 失敗の設計

- 失敗した瞬間、**何がダメだったか**が画面に出る（「はみ出していない」「破れた」）
- **もう一度**が常に同じ位置（右下）にある
- 失敗しても**記録が残る**（ベスト更新なら「自己ベスト更新！」バッジ）
- 理不尽にしない: 判定は**見た目どおり**（設計図の線がそのまま境界）

---

## 5. 技術的な「軽さ」の作り方

- 3Dは `three.js` を **importmap でCDNから**（バージョン固定 `0.160.0`）
- 影は**使わない**（`ShadowMap` 無効）→ スマホで軽い
- パーティクルや箱は `InstancedMesh` で1ドロー
- 画像は `CanvasTexture` で生成（ファイル0枚）
- 音は全部 `WebAudio` 合成（ファイル0枚）
- ゲーム本体は 60〜90KB に収める

---

## 6. この知識を使うときのルール（パクリ防止）

- **題材を変える**（設計図→別の世界観、積み木→別の物理）
- **操作を変える**（つまんで離す→なぞる／回す／息を吹く）
- **画面構成を変える**（同じ「線＋方眼」を使わない）
- 参考にするのは**手法だけ**。色・文言・ロゴ・レイアウトは自分で決める。
