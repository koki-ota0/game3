# WORKFLOW — 1日1本を、無理なく回す手順

## 1日の流れ（目安 3〜4時間）

| 時間 | やること |
| --- | --- |
| 朝（5分） | `daily-nudge` の Issue を見る。昨日の反応（X のいいね・リポスト）を1つだけ読む |
| 企画（20分） | 「日常のちょっとした疑問・妄想」から1つ選ぶ。**遊びの一言**（例:「10秒を、時計を見ずにぴったり止める」）を決める。数字で仕様を決める（制限時間・回数・判定のしきい値） |
| 実装（60〜120分） | `npm run new -- <slug> "タイトル" "キャッチ"` → `site/<slug>/index.html` を作りこむ。**まず遊べる形**にして、そのあと演出 |
| テスト（20分） | スマホの実機で縦持ち。`npm run build && npm run check`。指で隠れる所・押しにくい所をメモ |
| 直し（30〜60分） | メモを上から順に1つずつ。「気づいたこと」は `games.json` の `notes` に残す（＝説明ページの「作っていて変えたところ」になる） |
| 公開（10分） | `games.json` の `status` を `published` に。`npm run build && npm run check` → PR → merge |
| 発信（10分） | X に「タイトル＋1行＋URL＋`#ブラウザゲーム`」。可能なら15秒の動画 |

## ブランチとPR

- 新作: `game/<slug>`（1ゲーム = 1PR）
- 直し: `fix/<slug>-<内容>`
- サイト自体の改善: `site/<内容>`

PR の本文には **「何を・なぜ変えたか」** を3行で。スクショか GIF を1枚。
merge は自己マージでよい（レビュー待ちはしない。1日1本の速度を優先）。

## ゲームを作るときの約束（AIにも守らせる）

1. **1ファイル**（`site/<slug>/index.html`）。CSS/JS はインライン。
2. 外部から読んでよいのは **three.js（jsDelivr の 0.170.0）・フォント・計測/広告タグ** だけ（`tools/check.js`）。
3. 画像は **canvas で描く**（ファイルを増やさない）。音は **Web Audio で鳴らす**（mp3 を置かない）。
4. `env(safe-area-inset-*)` を使う。**指で隠れる位置にボタンを置かない**。
5. **時計・スコアの表示は、ゲームの手がかりにならないように**（『10秒、ぴったり。』では、背景の粒の動きを時間と切りはなした）。
6. セーブは `localStorage`。**個人情報を入力させない**。
7. 最初の版は **説明なしで遊べる**こと。タイトル画面に1行だけルールを書く。

## 出したあと（N.K. Works が実際にやっていること）

- 出したその日に、**もう1〜3本の小さな直し**を出す（「一時停止が無い」「文字が大きすぎる」「判定がきびしい」）。
- 翌日、反応が良かった所を **次のゲームの型** にする（診断系 → 別の診断系、タイムアタック → 別のタイムアタック）。
- **やめた仕掛け**を `notes` に書く。次の企画で同じ失敗をしない。

## 数えること（週1回）

- 公開本数（`games.json` の `status: published` の数）
- 続いた日数（`daily-nudge` の Issue が立たなかった日）
- ゲームごとの反応（X の表示回数）→ 次の1週間で作る型を1つ決める

## やめたこと（追記していく）

- （例）3D の凝った演出から作り始める → 遊べる形が遅くなるので、**2Dの当たり判定で先に遊べる形**にしてから3Dにする。
